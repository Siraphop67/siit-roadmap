## ปัญหา

วันนี้ผู้ใช้วางลิงก์โปรไฟล์ GitHub แล้วระบบ **ตัดสินใจแทนเขาทั้งหมด** — หยิบ 8 repo
ที่แก้ล่าสุดที่ไม่ใช่ fork มาอ่านรวดเดียว ผู้ใช้ไม่เห็นก่อนว่าจะอ่านอะไร และเลือกไม่ได้

วัดกับโปรไฟล์จริง (`github.com/TommyTheSecond`) ได้ 4 repo · 13,749 ตัวอักษร

🔴 **และ repo ส่วนตัว 3 อันของเจ้าของบัญชีนั้นหายไปเงียบ ๆ**
เพราะเราเรียก GitHub API แบบไม่ล็อกอิน ซึ่งเห็นเฉพาะ repo สาธารณะ
หนึ่งในนั้นคือ `acoustic-delamination-detection` ที่มีผลวัดจริง 87.1% LOPO —
**ผลงานที่ดีที่สุดของเขาไม่เคยถูกอ่าน และหน้าจอไม่ได้บอกว่าข้ามไป**

สำหรับผลิตภัณฑ์ที่ขายว่า *"เราอ่านจากผลงานจริงของคุณ"* การเงียบแบบนี้รับไม่ได้

## สิ่งที่จะทำ

ให้ผู้ใช้ **เห็นรายชื่อ repo ก่อน แล้วติ๊กเองว่าจะให้อ่านอันไหน**

หลักการเดียวกับหน้ายืนยันผลสกัด (กติกาข้อ 3) — ระบบเสนอ ผู้ใช้ตัดสิน

### ที่ตัดสินใจแล้ว

| ประเด็น | เลือก | เหตุผล |
|---|---|---|
| เป้าหมายหลัก | ความไว้ใจ ไม่ใช่ความเร็ว | ผู้ใช้ต้องเห็นก่อนว่าจะอ่านอะไร |
| ขอบเขต | **repo สาธารณะเท่านั้น** | OAuth กินเวลาหลายวัน · เหลือ 3 สัปดาห์ถึง Hack Days · และต้องเก็บ token ที่เข้าถึงโค้ดส่วนตัวได้ ซึ่งทีมยังไม่มีระบบเก็บความลับ |
| จังหวะเลือก | **เลือกก่อนวิเคราะห์** | ถ้าวิเคราะห์ก่อนแล้วค่อยกรอง = ส่งผลงานที่ผู้ใช้ไม่ได้อนุญาตเข้า Gemini ไปแล้ว ขัดกับที่ API บังคับ `consent: true` |
| ค่าเริ่มต้น | **ไม่ติ๊กอะไรไว้เลย** | ติ๊กไว้ให้ล่วงหน้าคือรูปแบบเดียวกับช่องยินยอมที่ติ๊กมาให้ ซึ่งทำให้ฟีเจอร์นี้เป็นแค่ของประดับ |

### ที่ **ไม่** ทำในรอบนี้

- **OAuth / personal access token** — ดูตารางข้างบน · ถ้าทีมจะทำทีหลัง หน้าจอไม่ต้องเปลี่ยน
  เปลี่ยนแค่ที่มาของรายชื่อ
- **แก้ตัวคั่น `## {name}`** — README มีหัวข้อ `##` ของตัวเอง จึงแยกไม่ออกว่า repo ไหนจบตรงไหน
  แต่ `ExtractedSkill` ไม่ได้เก็บว่าทักษะมาจาก repo ไหน ความเสียหายจริงจึงมีแค่ LLM สับสนเล็กน้อย
  และการเลือกน้อย repo ก็ทำให้ข้อความสั้นลงอยู่แล้ว — แยกเป็นงานอื่น

## รูปร่าง API

```
POST /portfolio/github/list   { url }
  → { owner, repos: [ { name, description, language, updated_at, has_readme } ], note }
  🔓 ไม่เก็บอะไร ไม่ต้องขอความยินยอม — ชื่อ repo สาธารณะไม่ใช่ผลงานส่วนตัวของใคร

        ↓  ผู้ใช้ติ๊กเอง (ไม่มีอะไรติ๊กไว้ให้)

POST /portfolio/github        { user_id, url, repos: [...], consent }
  → ดึงเฉพาะที่เลือก แล้วเข้าเส้นทาง _store_document() เดิมไม่เปลี่ยน
```

**ไม่ส่ง `repos` มา = ทำงานเหมือนเดิมทุกประการ** ของเดิมจึงไม่พัง

## 🔴 จุดที่พลาดแล้วอันตราย

`repos` มาจากเบราว์เซอร์ แล้วถูกเอาไปต่อใน `{GITHUB_API}/repos/{owner}/{name}`

ชื่อแบบ `../../users/someone` จะเปลี่ยนเส้นทางที่เรียกทั้งเส้น **ต้องตรวจสองชั้น**
1. ชื่อต้องตรงรูปแบบ `^[A-Za-z0-9._-]+$`
2. ชื่อต้องอยู่ในรายการ repo จริงของเจ้าของบัญชีนั้น

## แผนการทดสอบ

ใช้ client ปลอมทั้งหมด **ไม่ยิงเน็ตจริง** (`from_github` รับ `client=` อยู่แล้ว)

| เทสต์ | คุมอะไร |
|---|---|
| อ่านรายชื่อได้ + ข้าม fork | พฤติกรรมหลัก |
| เรียงตามวันที่แก้ล่าสุด | ผู้ใช้เห็นของใหม่ก่อน |
| ไม่พบผู้ใช้ → IngestError ที่อ่านรู้เรื่อง | กติกาข้อ 5 |
| ชื่อ repo มี `../` → ถูกปฏิเสธ | ความปลอดภัย |
| ชื่อที่ไม่ใช่ของเจ้าของบัญชี → ถูกปฏิเสธ | ความปลอดภัย |
| เลือกแล้วดึงเฉพาะที่เลือกจริง | พฤติกรรมหลัก |
| ไม่ส่ง `repos` → ผลเหมือนเดิม | ของเดิมไม่พัง |
| เลือกศูนย์อัน → 400 พร้อมข้อความบอกทาง | กติกาข้อ 5 |
| บัญชีที่ไม่มี repo สาธารณะ → บอกตรง ๆ | ไม่เงียบ |
