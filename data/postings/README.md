# เก็บประกาศงานจริง — อ่านไฟล์นี้ก่อนเก็บอันแรก

> เจ้าของงาน: **🅴** ([`docs/TEAM.md`](../../docs/TEAM.md) §3) · เดดไลน์ **30 ส.ค.** · เป้า **30–50 ประกาศ**
> ไม่ต้องเขียนโค้ดเลย — คัดลอกไฟล์แม่แบบ วางข้อความ กรอกหัวไฟล์ จบ

---

## ทำไมงานนี้ตัดไม่ได้

ตอนนี้ requirement ของทั้ง 8 อาชีพ (61 ข้อ) **เราเขียนขึ้นเอง** ทุกอาชีพจึงมี
`data_status: placeholder` และ `posting_count: 0` — ซึ่งระบบรายงานตามจริงอยู่ตลอด

**ถ้าไม่มีไฟล์ในโฟลเดอร์นี้ เราขึ้นเวทีแล้วอ้างไม่ได้เลยว่าเส้นทางที่แสดงมาจากตลาดงานจริง**

ประกาศงานที่เก็บไว้ตรงนี้จะถูกใช้สองทาง:
1. **ทำให้ requirement เป็นของจริง** — ทักษะไหนปรากฏในกี่ประกาศ (`appears_in_n_postings`)
2. **แสดงงานจริงให้ผู้ใช้เห็น** — *"งานนี้เปิดรับอยู่ คุณห่าง 3 ก้าว และนี่คือ 3 ก้าวนั้น"*

ทั้งสองอย่างใช้ไฟล์ชุดเดียวกัน **เก็บรอบเดียวพอ** — นี่คือเหตุผลที่หัวไฟล์มีช่องเยอะกว่าที่ใช้วันนี้

## 🔴 ห้ามเขียน scraper

ผิดเงื่อนไขการใช้งานของเว็บหางานเกือบทุกเจ้า · เก็บด้วยมือ 30–50 อันใช้เวลาประมาณ 1 วัน
เหตุผลเต็มอยู่ใน [`docs/DECISIONS.md`](../../docs/DECISIONS.md) D11

**นี่ไม่ใช่ทางลัดเพราะเป็นต้นแบบ — เป็นข้อจำกัดถาวร** ต่อให้ระบบโตแค่ไหนก็ยังเขียน scraper ไม่ได้
สิ่งที่จะเปลี่ยนเมื่อโตคือ *จำนวน* กับ *ใครเป็นคนเก็บ* ไม่ใช่ *วิธี*

## เก็บยังไง

```bash
cp data/postings/_TEMPLATE.md data/postings/2026-08-20-scg-process-engineer.md
```

**ชื่อไฟล์คือ id ของประกาศ** — ตั้งเป็น `วันที่เก็บ-องค์กร-ตำแหน่ง` เป็นตัวพิมพ์เล็กกับขีดกลาง
(ไฟล์ที่ขึ้นต้นด้วย `_` จะถูกข้าม ใช้กับแม่แบบและตัวอย่าง)

แล้วตรวจว่าที่กรอกมาถูกรูปแบบ:

```bash
make check-postings
```

สั่งได้บ่อยเท่าที่ต้องการ ไม่ต้องเปิด backend ไม่พังอะไร

## หัวไฟล์ — ช่องที่**ต้องกรอก**

| ช่อง | ตัวอย่าง | หมายเหตุ |
|---|---|---|
| `org` | `บริษัท ปูนซิเมนต์ไทย จำกัด (มหาชน)` | ชื่อองค์กรตามที่ประกาศเขียน |
| `title` | `Process Engineer (New Graduate)` | ชื่อตำแหน่งตามประกาศ อย่าแปล |
| `url` | `https://…` | ลิงก์ตรงไปที่ประกาศ |
| `collected_at` | `2026-08-20` | วันที่เก็บ **ไม่ใช่วันที่ประกาศ** |
| `collected_by` | `เอิร์ธ` | ใครเก็บ — ไว้ถามต่อได้ตอนข้อมูลดูแปลก |
| `sector` | `private` | `private` · `government` · `state_enterprise` · `academic` |
| `employment_type` | `new_grad` | `new_grad` · `internship` · `coop` · `experienced` |

`sector` สำคัญกว่าที่คิด — เป็นตัวที่ทำให้ระบบบอกได้ว่า *"งานนี้เป็นเอกชน ทุนของคุณไม่ให้ไป"*

## หัวไฟล์ — ช่องที่**ไม่บังคับ แต่ใส่ตอนนี้ง่ายกว่ามาก**

ทุกช่องข้างล่างนี้ *อยู่ในตัวประกาศอยู่แล้ว* จะย้อนมาอ่านทีหลังก็ได้
แต่ตอนคุณกำลังอ่านประกาศอยู่ มันใช้เวลาเพิ่มอันละ 10 วินาที ส่วนการย้อนกลับมาอ่าน 40 ประกาศใหม่คือครึ่งวัน

| ช่อง | ตัวอย่าง | ใช้ทำอะไร |
|---|---|---|
| `target_id` | `PROC-ENG` | อาชีพในระบบที่คุณเดาว่าตรง · ไม่แน่ใจใส่ `null` |
| `location` | `ระยอง` | กรองตามทำเลตอนแสดงงานจริง |
| `salary_text` | `"25,000–30,000 บาท/เดือน"` | ใส่**ตามที่ประกาศเขียน** ห้ามเดาเอง ไม่เขียนไว้ให้ `null` |
| `posted_at` | `2026-08-15` | วันที่ประกาศออก |
| `closes_at` | `2026-09-15` | ปิดรับเมื่อไหร่ · ไว้ซ่อนงานที่หมดอายุ |
| `requires_field` | `[ChE, ME, IE]` | สาขาที่ประกาศระบุ |
| `requires_gpa` | `2.75` | เกรดขั้นต่ำที่ประกาศระบุ |
| `requires_education` | `จบปริญญาตรี` | วุฒิขั้นต่ำที่ประกาศระบุ |
| `note` | `ประกาศนี้รวม 3 ตำแหน่งไว้ด้วยกัน` | อะไรที่คนอ่านทีหลังควรรู้ |

> **URL ตายได้ ประกาศถูกลบได้** — ของที่กู้คืนไม่ได้จริง ๆ มีสามอย่าง: `url` · `collected_at` · **ตัวข้อความประกาศ**
> ที่เหลืออ่านย้อนจากข้อความได้เสมอ เพราะงั้นถ้าเร่ง ให้เก็บสามอย่างนี้ให้ครบก่อน

## ตัวข้อความประกาศ — ส่วนใต้ `---`

**วางตามต้นฉบับทั้งหมด ห้ามสรุป ห้ามตัด ห้ามเรียบเรียงใหม่**

ระบบจะสกัดทักษะจากข้อความนี้ แล้ว**ชี้กลับไปที่ตัวอักษรตำแหน่งที่เท่าไหร่**ในข้อความ
(กติกาข้อ 2 ใน [`docs/TEAM.md`](../../docs/TEAM.md) — หลักฐานที่ชี้ไม่ได้จะถูกทิ้ง)

ถ้าคุณสรุปให้สั้นลง ทักษะที่สกัดได้จะชี้ไปผิดที่ หรือหายไปเลย

รวมส่วนพวกนี้มาด้วย เพราะเป็นที่ที่ requirement ซ่อนอยู่:
คุณสมบัติผู้สมัคร · หน้าที่ความรับผิดชอบ · ทักษะที่ต้องการ · สิ่งที่จะได้เรียนรู้

## 🔴 ก่อนวาง ให้ลบสามอย่างนี้ออกจากข้อความ

**repo นี้เป็น public** — อะไรที่วางลงไป คนทั้งอินเทอร์เน็ตอ่านได้

| ลบ | ทำไม |
|---|---|
| **อีเมลผู้รับสมัคร** | ข้อมูลส่วนบุคคลของคนที่ไม่ได้ยินยอม |
| **เบอร์โทรศัพท์** | เหมือนกัน |
| **ชื่อ HR ที่ระบุตัวตนได้** | เหมือนกัน |

`make check-postings` จะเตือนให้ถ้าเจอรูปแบบพวกนี้ แต่มันจับได้ไม่หมด — ตาคุณคือด่านสุดท้าย
ชื่อองค์กรกับชื่อตำแหน่งเก็บได้ตามปกติ ไม่ใช่ข้อมูลส่วนบุคคล

## เก็บจากไหนดี

กระจายให้ครบทั้ง 4 `sector` และครบทั้ง 8 อาชีพเท่าที่ทำได้
ถ้าเก็บแต่เอกชนสายซอฟต์แวร์ 40 อัน requirement ของอีก 7 อาชีพก็ยังเป็นของที่เราเขียนเองอยู่ดี

เป้าคร่าว ๆ: **อาชีพละ 4–6 ประกาศ** · และอย่างน้อย 5 อันจากภาครัฐ/รัฐวิสาหกิจ/มหาวิทยาลัย
เพราะจุดสาธิตเรื่องเงื่อนไขทุนต้องมีงานฝั่งนั้นให้ชี้จริง ๆ
