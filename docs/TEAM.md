# 1. สิ่งที่ทุกคนต้องเข้าใจตรงกัน

## เราสร้างอะไร — พูดให้ได้ในประโยคเดียว

> **เว็บหางานบอกว่ามีงานอะไร — ของเราบอกว่าจะไปถึงงานนั้นได้ยังไง**
> และเราไม่เชื่อสิ่งที่ผู้ใช้กรอกอย่างเดียว **เราอ่านจากผลงานจริงของเขา**

ถ้ามีคนถามว่า "ต่างจาก roadmap.sh ยังไง" คำตอบคือ:
**roadmap ของ roadmap.sh เหมือนกันหมดทุกคน — ของเราเริ่มจาก CV ของคุณ และบอกว่า*คุณ*อยู่ตรงไหนบนเส้นนั้น**

| # | กติกา | ทำไม | มีเทสต์คุมไหม |

# 3. ห้าบทบาท

> **หลักการแบ่ง: แบ่งตามคอขวด ไม่ใช่ตามความชอบ** · แต่ละคนเป็นเจ้าของไฟล์ของตัวเอง จะได้ไม่ชนกันเวลา merge

## 🅰 หน้า Roadmap  — *หน้าที่ผลิตภัณฑ์ทั้งอันมีอยู่เพื่อมัน*

**เป็นเจ้าของ** `frontend/app/roadmap/**`
**ต่อกับ** `GET /api/roadmap`

| ต้องทำ | รายละเอียด |
|---|---|
| ตัดสินใจว่าวาดเป็น **กราฟหรือรายการ** | 🔴 ยังไม่ตัดสินใจ และเป็นการตัดสินใจของคุณ · API ส่งให้ทั้ง `order_no` (รายการ) และ `edges` (กราฟ) แล้ว |
| แสดง 4 สถานะให้ต่างกันชัด | `current` ลงมือได้ตอนนี้ · `in_progress` มีบางส่วนแล้ว · `flexible` ทำเมื่อไหร่ก็ได้ · `locked` ยังกดไม่ได้ |
| **ติดป้ายว่าทักษะไหนมาจาก CV ทักษะไหนกรอกเอง** | กติกาข้อ 1 — ห้ามแสดงเหมือนกัน |
| หน้ารายละเอียดก้าว | ทางไปถึงหลายทาง + ตัวที่ติดเงื่อนไข **ต้องแสดงพร้อมเหตุผล ไม่ซ่อน** |

**ควรเป็นคนที่ทำ frontend ได้แข็งที่สุด** — นี่คือหน้าที่กรรมการจะจ้องนานที่สุด

## 🅱 หน้าส่งผลงาน + ตรวจผลสกัด — *หน้าที่สร้างความไว้ใจ*

**เป็นเจ้าของ** `frontend/app/portfolio/**`
**ต่อกับ** `POST /api/portfolio/{text|github|linkedin|upload}` · `GET /api/portfolio/{id}` · `POST /api/portfolio/{id}/confirm`

| ต้องทำ | รายละเอียด |
|---|---|
| รับผลงาน 4 ทาง | PDF · วางข้อความ · ลิงก์ GitHub · LinkedIn (ให้วางเอง + **บอกเหตุผลว่าทำไมดึงอัตโนมัติไม่ได้**) |
| ⭐ **ไฮไลต์ span ในตัว CV** | API ส่ง `raw_text` + `span_start/span_end` มาให้ · ระบายสีตรงตำแหน่งนั้นจริง ๆ |
| ให้ผู้ใช้ ✓ / ✗ / แก้ระดับ รายข้อ | กติกาข้อ 3 — ยังไม่ยืนยัน = ยังไม่นับ |
| ขอความยินยอมก่อนอัปโหลด | CV เป็นข้อมูลส่วนบุคคล API ปฏิเสธถ้าไม่ส่ง `consent: true` |

**⭐ หน้าไฮไลต์คือจุดที่พิสูจน์ว่าระบบอ่าน CV จริง ไม่ใช่เดา** — ถ้าเหลือเวลาให้ขัดหน้าเดียว ขัดหน้านี้

## 🅲 หน้าแรก + คลังอาชีพ + โปรไฟล์ + ชุดคอมโพเนนต์กลาง

**เป็นเจ้าของ** `frontend/app/page.tsx` · `frontend/app/targets/**` · `frontend/app/profile/**` · `frontend/components/**` · `frontend/lib/api.ts`
**ต่อกับ** `GET /api/meta` · `GET /api/targets` · `GET /api/targets/{id}` · `POST /api/profile`

| ต้องทำ | รายละเอียด |
|---|---|
| 🔴 **ทำ `lib/api.ts` + คอมโพเนนต์กลางให้เสร็จก่อนใครภายใน 3 วันแรก** | อีกสามคนรอใช้ ถ้าช้าทุกคนติด |
| หน้าแรก 2 ทางเข้า | "ยังไม่รู้ว่าอยากเป็นอะไร" / "รู้แล้ว อยากรู้ทางไป" |
| คลังอาชีพ + รายละเอียด | **อาชีพที่ถูกกรองออกต้องแสดงพร้อมเหตุผล ไม่หายเงียบ ๆ** (เงื่อนไขทุนกรองเอกชนออก = จุดสาธิต) |
| โปรไฟล์ | ชั้นปี · เกรด · เวลา · งบ · ทุน · ทักษะที่คิดว่าตัวเองมี |

## 🅳 ฝั่ง "ยังไม่รู้ว่าอยากเป็นอะไร" — *ทั้งฝั่ง ทั้ง backend และ frontend*

**เป็นเจ้าของ** `backend/app/api_discover.py` (สร้างใหม่) · `frontend/app/discover/**`
**ใช้ของที่มีแล้ว** `backend/app/engine/match_target.py` — เครื่องยนต์เสร็จและผ่านเทสต์กู้คืน 8/8 แล้ว เหลือแค่ห่อเป็น API กับหน้าจอ

| ต้องทำ | รายละเอียด |
|---|---|
| API แบบทดสอบ | ขอข้อถัดไป · ส่งคำตอบ · ดูผลจับคู่ (เรียก `match_targets` และ `next_best_item` ที่มีอยู่แล้ว) |
| ⭐ **แสดงผลระหว่างทำ** ทุก ~6 ข้อ | สิ่งเดียวที่คนในเธรด r/findapath ชมว่าดี — *"it gives feedback as you answer"* |
| ⭐ **บอกว่าทำไมยังถามต่อ** | *"ตอนนี้ 'หุ่นยนต์' กับ 'เครื่องกล' ยังแยกไม่ออก ขอถามอีก 4 ข้อ"* |
| ถ้าอันดับ 1–2 ยังไม่ห่างพอ | **บอกตรง ๆ ว่ายังแยกไม่ออก ห้ามยัดอันดับให้ดูมั่นใจ** — `MatchOutcome.separated` บอกให้แล้ว |
| จบด้วย **"อาชีพที่คุณอาจไม่เคยคิดถึง"** | `is_unconsidered` มีให้แล้ว |
| 🔴 แก้เรื่องคะแนนกองกัน | คะแนนดิบอยู่ที่ 0.88–0.96 ทุกอาชีพ **ห้ามเอาไปโชว์ตรง ๆ** ต้องแปลงเป็นค่าสัมพัทธ์ในกลุ่ม |

**เป็นงานที่แยกขาดที่สุด** — ทำได้โดยไม่ต้องรอใคร

# 5. สัญญาระหว่างกัน — ทำไมทำขนานกันได้

**API เสร็จและนิ่งแล้ว** ทุกคนจึงต่อกับสัญญาเดียวกันโดยไม่ต้องรอกันเอง

```bash
make backend          # แล้วเปิด http://localhost:8000/docs — เห็น endpoint ทั้ง 17 ตัวพร้อมตัวอย่าง
```

**กติกาเรื่องการแก้ API**
- ฝั่งหน้าเว็บ **ห้ามแก้ `backend/app/api.py` เอง** — ถ้าอยากได้ฟิลด์เพิ่ม บอก 🅳 หรือเปิด issue
- ถ้าจำเป็นต้องเปลี่ยนรูปร่าง response **ต้องบอกในกลุ่มก่อน** เพราะมีคนอื่นต่ออยู่
- เพิ่มฟิลด์ใหม่ = ปลอดภัย · ลบหรือเปลี่ยนชื่อฟิลด์ = ทำให้คนอื่นพัง
