# frontend-demo — ต้นแบบหน้าเว็บฝั่งผู้เรียน

> **โฟลเดอร์นี้แยกจาก `frontend/` โดยตั้งใจ — ไม่แตะ ไม่ทับ ไม่ conflict กับงานของใคร**
> `frontend/` คือ Next.js ตัวจริงที่จะ build ต่อ · `frontend-demo/` คือต้นแบบหน้าตา + flow ที่กดเล่นได้จริง ไว้ใช้สาธิตและตกลงดีไซน์กันก่อนลงมือเขียน component จริง

---

## เปิดยังไง

ดับเบิลคลิก `index.html` — จบ

ไม่ต้อง `npm install` ไม่ต้องรัน server ไม่ต้องต่อ backend
เป็น static HTML + JS ล้วน รันจากไฟล์ในเครื่องได้เลย

> ถ้าเปิดแล้วรูปไม่ขึ้น แปลว่าโฟลเดอร์ `img/` ไม่ได้มาด้วย — ต้องอยู่ข้าง `index.html` เสมอ

## ลองเล่นให้เห็นว่ามันคำนวณจริง

```
1. #/profile  → สาขา CPE · ปี 2 · ทุนรัฐบาล → บันทึก
   ↳ อาชีพภาคเอกชนถูกตัดออกจริง พร้อมเหตุผล

2. #/careers  → วิศวกรข้อมูล → ตั้งเป็นเป้าหมาย
   ↳ เส้นทางถูกสร้างจากกราฟ prerequisite · ตอนนี้ 0%

3. #/upload   → ใส่ตัวอย่าง → ติ๊กยินยอม → อ่านผลงาน
   ↳ สกัดคำจริง ได้ตำแหน่งตัวอักษรจริง

4. กด "ใช่ ทำได้" ทีละข้อ
   ↳ % ขยับจริงทุกครั้ง · ก้าวที่ล็อกอยู่ค่อย ๆ ปลดล็อก
```

## 🔒 กติกาที่โค้ดนี้บังคับไว้แล้ว

ตรงกับ `docs/TEAM.md` §1 และ `frontend/lib/api.ts` — **ห้ามแก้ให้หลุด**

1. **ทักษะจาก CV กับที่กรอกเอง แยกกันเสมอ** — เส้นทึบ = มีหลักฐาน · เส้นประ = กรอกเอง ไม่เคยรวมกัน
2. **ยังไม่ยืนยัน = ยังไม่นับ** — `status: "pending"` ไม่ถูกเอาไปคำนวณ %
3. **อาชีพที่ถูกกรองออก ต้องแสดงพร้อมเหตุผล** — หายเงียบ ๆ คือบั๊ก
4. **แยกเงื่อนไขถาวรกับเงื่อนไขตามเวลา** — สาขา/ทุน = ตัดจริง · ชั้นปี = "สมัครได้เมื่อขึ้นปี 3" ไม่ตัด
5. **"ทำไมถึงเสนอ" กับ "สิ่งที่ควรรู้ก่อนเลือก" อยู่คนละที่** — รวมกันเมื่อไหร่ หน้าจอจะอ่านได้ว่า "เสนองานนี้เพราะคุณไม่อยากทำ"
6. **อาชีพที่ย้อนที่มาไม่ได้ ไม่ถูกเสนอเลย** — `matchTargets()` กรองทิ้ง แม้รายการจะว่าง
7. **คะแนนคือตำแหน่งเทียบกลุ่ม ไม่ใช่ % ความเหมาะสม** — ต้องมีคำกำกับทุกที่ที่แสดง
8. **ห้ามใช้คำว่า AI** — ตัวสกัดเป็นการจับคำสำคัญ พูดตามจริงว่า "จับคำสำคัญ"
9. **ตัวเลือกที่ติดเงื่อนไข ยังแสดงอยู่พร้อมเหตุผล** — ไม่หายไปจากรายการ

## 🔴 สิ่งที่ยังไม่จริงในเดโมนี้

พูดตรง ๆ ไว้ก่อน จะได้ไม่เผลอไปพูดเกินบนเวที

- **ข้อมูลเป็นชุดย่อ** — 38 ทักษะ (ของจริง 73) · คำถาม 12 ข้อ (ของจริง 41 มิติ) · ทางไปถึงใส่มือ
- **ยังไม่ได้ต่อ backend** — คำนวณในเบราว์เซอร์ทั้งหมด `NEXT_PUBLIC_API_BASE` ยังไม่ถูกใช้
- **การจับคู่อาชีพเป็นเวอร์ชันย่อ** — น้ำหนักเขียนมือใน `app-data.js` ไม่ใช่โปรไฟล์ O\*NET เต็ม
- **อ่าน PDF ไม่ได้** — รับเฉพาะวางข้อความ (ตัวจริงใช้ PyMuPDF ฝั่ง server)
- **ชื่อวิชาเป็นชื่อทั่วไป** — ไม่ใช่รหัสวิชา SIIT จริง จงใจไม่ใส่ของปลอมที่ดูเหมือนจริง
- **`0 ประกาศงาน`** — ตรงกับของจริง ยังไม่มีใครเก็บประกาศ
- **ยังไม่มีชื่อระบบ** — ทุกที่เขียน `[ชื่อระบบ]`

## เปลี่ยนของบ่อย ๆ ตรงไหน

**ชื่อระบบ** — `app-ui.js` บรรทัดบนสุด แก้ที่เดียว ขึ้นทุกที่
```js
const APP_NAME="[ชื่อระบบ]";
```

**สีหลัก** — `index.html` ใน `:root`
```css
--g:#0FBE6E;
```

**ความเร็ว marquee** — `index.html` ที่ `.track` (น้อย = เร็ว)
```css
animation:slide 42s linear infinite;
```

**รูปประจำอาชีพ** — `app-data.js` ท้ายไฟล์
```js
const CAREER_IMG={ "DATA-ENG":"img/c-data.jpg", ... }
```

**เพิ่มคำที่ตัวสกัดรู้จัก** — `extract.js` ใน `DICT`
```js
"T-PY":{th:"...",lv:2,kw:["Python","ไพทอน","django","flask"]}
```

## ขั้นต่อไป

1. ตกลงกันว่าเอาดีไซน์นี้ไหม ก่อนเริ่มเขียน component จริงใน `frontend/`
2. ถ้าเอา → ย้าย token สี/ฟอนต์เข้า `frontend/app/globals.css` เป็น Tailwind v4 `@theme`
3. ต่อ API จริง — แก้ `app-engine.js` ให้เรียก `frontend/lib/api.ts` แทนคำนวณเอง
4. ตั้งชื่อระบบสักที 🙂

> เดโมนี้ **ไม่ได้จะไปแทน `frontend/`** — มีไว้ตกลงหน้าตาและ flow ให้จบก่อน จะได้ไม่ต้องรื้อ component ทีหลัง
